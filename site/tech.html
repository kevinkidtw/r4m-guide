一、兩套遙控的差別

V7RC（手機）KSB 搖桿（micro:bit radio）
傳輸BLE 藍牙，點對點連線2.4GHz 廣播
別校干擾不會（手機獨佔一台車）會，靠頻段、封包名、配對三層隔離
現場的問題「哪一台是我的」→ 按 A 看藍牙名稱「別人的訊號會進來」→ 配對＋交叉測試
同一支程式並用不行：MakeCode 啟用藍牙後 radio 會被移除—

二、主控盒腳位

主控盒左輪（方向／速度）右輪機構 1機構 2
1269P13 / P14P15 / P16P12 / P2P1 / P8
1409P15 / P14P0 / P16P13 / P8P2 / P1
  • 兩組腳位表都內建在程式裡，開機選單選主控盒即可切換。
  • 第 4 組馬達的速度腳在 B 車就是閘門伺服腳（1269 → P8，1409 → P1）。B 車不驅動第 4 組，那支腳就是乾淨的伺服腳，不必改接線。
  • B 車實際使用 3 馬達＋1 伺服＝4 路 PWM，剛好是 micro:bit V2 的上限。
  • micro:bit 所有 PWM 輸出共用同一個頻率，車上有伺服就不能改 PWM 頻率。兩台車都使用預設 50Hz。

三、馬達方向預設值

組合狀態
1409 ＋ V7RC✔ 實車驗證
1269 ＋ V7RC✔ 實車驗證
1269 ＋ KSB 搖桿✔ 與實際輸出逐項比對一致
1409 ＋ KSB 搖桿⚠ 由上面三項推得，第一次試車要確認

兩種主控盒的輪子方向其實一樣，差別在遙控器：KSB 搖桿往上推數值變小，V7RC 往上推數值變大。所以 V7RC 版兩組都是 [true, false, …]，KSB 版兩組都是 [false, true, …] 再加上 反轉_轉向 = true。某台盒子接線不同時，單獨改 反轉_1269 或 反轉_1409。

第一次試車的順序

  1. 輪子架空。
  2. 搖桿往前：兩輪都要往前轉。哪一輪反了，改這台主控盒那一組的第 0 格（左）或第 1 格（右）。
  3. 搖桿往右：車子要往右轉，反了改 反轉_轉向。
  4. 機構鍵：升降與夾爪方向不對，改第 2 格／第 3 格。
  5. 落地跑一圈，再調 曲線量 和 全域限速。

五、決賽鎖定

車端程式（01、04）最上面有一段鎖定設定。決賽前改成 true 並寫死車編號、主控盒，開機選單就不會被誤按改掉；配對入口仍保留，方便臨時換遙控器。

const 鎖定設定: boolean = false      // 決賽前改成 true
const 鎖定_車編號: string = "A"      // "A" 或 "B"
const 鎖定_主控盒: number = 1269     // 1269 或 1409

型別標註（: number、: string）不能刪，刪掉後改值會編譯錯誤。

六、KSB 訊號隔離細節

  • 群組固定 173，封包名稱固定 R4，遙控器每 30ms 送一包，一包帶搖桿與 7 顆按鍵的完整狀態。
  • 頻段由遙控器晶片序號算出：((序號 ^ (序號 >> 16)) & 0xFFFF) % 14，對應 14 個避開 WiFi 1／6／11 與藍牙廣播頻道的頻段：22–24、48–51、72–78。
  • 車子配對時每 120ms 換一個頻段輪流聽，2 秒內就能找到遙控器，記下序號後存 Flash。
  • 車子每 500ms 回報一次給遙控器；遙控器 1.2 秒沒收到就震動警告。
  • 主辦要求固定頻段時，遙控器與車子都按住 A＋B 開機（顯示 L），全部固定在 band 7，配對照樣有效。

七、V7RC 封包與探測器

Game ADV 介面送出 SRT 開頭、19 字元的封包，每秒約 33 包；四個通道 1000–1500–2000：通道 1 左搖桿左右、通道 2 左搖桿上下、通道 3 方向鍵上下、通道 4 方向鍵左右。放開時回到 SRT1500150015001500。

改用其他 V7RC 介面前，先燒 06_V7RC封包探測器_GameADV用.ts（下載）測一次通道順序與數值範圍，再改車端程式頂端的 CH_ 通道設定。

八、待實測項目

  • 1409 ＋ KSB 搖桿的馬達方向。
  • B 車行走時閘門會不會抖、會不會自己動。
  • KSB 配對：兩隊錯開配對後的交叉測試，以及配對是否在 2 秒內完成。
  • V7RC 的 ↖ ↗ 好不好按；微調轉速、微調最短毫秒 依選手習慣微調。
  • C 車全部參數（里程、轉角、取料、卸料、閘門角度）都需要在場地上實測。
